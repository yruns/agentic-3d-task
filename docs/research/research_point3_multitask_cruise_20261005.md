## 二 选题过程与取舍

### 2.1 主动关键帧获取：降为子模块

最初的候选是"价值引导的主动关键帧获取"：把研究一流式化为在线关键帧记忆，训练一个轻量证据价值模型决定去哪看、看哪些、何时作答，以 A-EQA 为主评测。没有作为主线，原因有三：

1. **与研究一的定位冲突。** 可学习的证据价值被写成研究一启发式的"升级替代"，主动获取又被写成"补研究一做不到的事"，研究一读起来像过渡品。
2. **范围偏小。** 其中的探索部分本质就是 frontier 策略；剩下的"到达后看清、看全、看到关系"只是巡航中的一个子问题。
3. **近邻已覆盖一部分。** [HFLEX-EQA](https://arxiv.org/abs/2609.26360)（2026 年 9 月预印本）已经实现单物体近看视点：判定已见物体相关后，围绕物体采样位姿，按可见顶点比例和画面内比例选视角。

该方向保留为研究内容 3.2 中的核验子模块，包括到达后的近看视点与目标—参照联合可见视点。

### 2.2 其他排除的方向

| 方向 | 排除理由 |
| --- | --- |
| 长程任务执行（PARTNR 等） | 与研究一、二联系弱，工程量对 3–5 个月偏大 |

## 三 任务定义

### 3.1 与其他巡航任务的区别

其他巡航任务一次只给一个目标，完成后环境和记忆都会重置。连续多任务巡航有三点不同：

1. **记忆跨任务保留，并被单独评测。** 基准按子任务序号统计成功率与 SPL，专门衡量记忆复用。
2. **任务逐个到达、形式混合。** 下一个目标在当前任务完成后才给出，不能像 LH-VLN 那样提前拿到全部阶段整体规划；目标可以是类别、语言描述、图片或问题。
3. **瓶颈随时间转移。** 单目标导航每次从零开始，核心是探索；连续任务越往后，越多目标已在记忆中，瓶颈转向三件事：召回之前见过的东西、在多个同类候选中认对实例、判断记忆是否可信。这正是研究一、二的能力范围。

### 3.2 已有证据

- [GOAT-Bench](https://arxiv.org/abs/2404.06609)：有记忆时，episode 后段子任务的 SPL 提高约 1.5–1.9 倍；CLIP 特征难以编码实例与空间信息，语言目标表现较差。
- GOAT-Bench 的语言目标由仿真器中的空间与语义信息、BLIP-2 提取的属性和 ChatGPT-3.5 自动生成，包含属性、邻近物体关系和所在房间，形式接近 NR3D 的指代描述。
- [GOAT 系统（RSS 2024）](https://arxiv.org/abs/2311.06430)：成功率从第 1 个目标的 60% 升到第 5–10 个目标的 90%；整体上语言目标成功率 68%，去掉实例区分后降到 28%。
- [Sequential-EQA](https://arxiv.org/html/2607.21571)（2026-07 预印本）：同场景连续提问时，空间锚定的记忆带来准确率 +33.3%、导航代价 −53.3%。

### 4.3 解读

- 绝对值上，单任务经典基准高出一个量级，主要因为它们早发表 5–8 年。按年均粗算：R2R 约 220 次/年，OpenEQA 约 150 次/年，GOAT-Bench 约 60 次/年，与同期的 HM3D-OVON 相当。
- GOAT-Bench 是连续多任务方向的事实标准：3D-Mem、HIMM、MetaNav、EvoMemNav、MTU3D 等都在上面报告结果，可对比的基线最多。
- LangMap、LMEE-Bench、Sequential-EQA 太新，引用少，可复现性未经检验，只作补充实验或协议参考。
- 单任务经典基准引用高，但非常拥挤，而且不评测记忆复用，研究一、二的作用体现不出来。巡逻、巡检类任务目前没有广泛使用的室内仿真基准。

主基准因此确定为 GOAT-Bench 与 A-EQA。A-EQA 属于 OpenEQA 的 HM3D 部分，与研究二使用的 ScanNet 部分同源；两个基准都已被 3D-Mem 的官方代码支持。

## 五 研究内容

### 5.1 研究内容 3.1 记什么：在线持久记忆与统一任务检索（以研究一为核心）

- **在线持久记忆。** 在 3D-Mem 的在线物体地图上，维护研究一所需的增量可见性记录和关键帧记忆。记忆跨任务不清空；重访同一区域时，合并同一实例的多视角观测。
- **研究一的最小改造。** 把 `src/keyframe/keyframe_selector.py` 中的 `_compute_visibility_scores`（L601）、`get_joint_coverage_views`（L663）、`_pose_aware_gain`（L734）抽成作用于增量记录的纯函数；离线 `KeyframeSelector` 的行为保持不变，以 NR3D hit@3 回归测试兜底。
- **统一目标表示。**
    - 类别与语言描述：走研究一的 `parse_query_hypotheses`（L970）和 `src/keyframe/query_executor.py` 的关系约束定位。
    - 图片目标：先由大模型描述成结构化查询，再叠加图像特征匹配分。
    - 问题：走研究一的证据检索。
    - 四类输入统一输出"候选实例 + 证据关键帧 + 关系满足度"。
- **核验结果写回。** 研究二核验确认的实例属性与关系（例如"窗边的棕色椅子 = 实例 12"）写回物体的 enrichment 字段。研究一本来就依赖 `enriched_objects.json`，写回后，后续任务可以直接命中。
- **衡量指标。** 记忆命中率（检索候选中是否包含真实实例，可用 HM3D 语义标注自动判定）、后段子任务 SPL、每次决策的图像 token 数随记忆规模的变化。

### 5.2 研究内容 3.2 怎么用：召回、核验、探索决策与实例消歧（以研究二为核心，零样本）

- **决策回路。** 每个任务根据检索结果，在"前往记忆实例、先核验、前沿探索、直接作答"之间选择。零样本版本由冻结大模型基于结构化证据决策；探索部分直接复用 3D-Mem 的前沿快照，不作为贡献。
- **记忆上的实例消歧。** 有多个同类候选时，移植研究二 NR3D 的工具（画框、按参照物做空间比较、取帧）让大模型判别，代码来源为 `src/codex_agent/nr3d/tools/`。研究二在 NR3D strat600 上的 Acc@0.25 为 84.5%（[NR3D 记录](../benchmark/nr3d/README.md)），对应的正是这类关系型消歧能力。
- **到达后的停止核验与近看视点。** 到达后用当前观测再与描述核对一次，不符则重新选择候选；必要时前往单个物体或目标—参照可同时看清的视点。
- **衡量指标。** 同类错实例率、过早停止率、语言目标成功率；A-EQA 中空间类与定位类问题的得分。

### 5.3 研究内容 3.3 越用越好：可验证奖励驱动的决策学习与自举迭代

- **决策校准器。** 一个小模型（MLP 或 2–3 层 Transformer）。输入研究一、二给出的结构化特征：候选得分、同类候选数、关系满足度、可见度、距离、目标模态、大模型核验结论；输出"该实例为真目标的概率"及动作选择。研究一的输出是它的输入特征，它不替代研究一。
- **可验证奖励。** 在 GOAT-Bench 训练场景（145 个，去掉开发用场景）采集决策状态。仿真器真值直接给出"是否为真实实例""是否成功""路径长度"，不需要大模型评审。先监督训练，再以"成功 − λ·路径 − μ·大模型调用次数"为奖励，做单步决策的 GRPO（上下文多臂赌博机形式）。
- **自举迭代（RSI）。** 当前智能体部署到训练场景 → 仿真器验证结果 → 新状态加入训练集 → 重训校准器 → 再部署。做 2–3 轮并报告逐轮改进；所有轮次只使用训练场景。
- **衡量指标。** 校准误差（ECE）、成功率与 SPL、每个任务的大模型调用次数、逐轮改进曲线。

### 5.4 可选扩展（时间充裕时二选一）

- **工具自生成（代码层的 RSI）。** 研究一的空间关系词表是固定的（on、near、next_to、between 等）。训练集语言目标中出现无法执行的关系时，由研究二的 Codex 智能体编写新的关系函数，并在训练目标上自动验证：能否把真实实例排在同类干扰项之前。通过验证后才加入研究一的关系库。近邻为 [VADAR](https://arxiv.org/abs/2502.06787)（CVPR 2025）。这条路线让研究一越来越强。
- **小模型适配（参数层）。** 用 LoRA + GRPO 微调 Qwen3-VL-8B 做记忆候选消歧，奖励为"是否选中真实实例"，作为 GPT-5.x 的低成本替代。需要 2–4 张卡、约 3–4 周。

### 5.5 拟定创新点

1. 面向连续多任务的在线持久场景记忆与统一结构化检索：把研究一扩展为跨任务、跨目标模态（类别、语言、图片、问题）的记忆检索接口，并用核验结果在线修正检索索引。
2. 召回、核验、探索协同决策与基于三维关系的实例消歧：把研究二的工具化推理用于记忆候选判别和到达后的停止核验，降低同类错实例与过早停止。
3. 可验证奖励驱动的决策校准与自举迭代：以仿真器真值为奖励训练轻量决策校准器，通过"部署—验证—再训练"持续改进，同时减少大模型调用。

以上为拟定表述，需经第 1–2 周的立题门槛与后续实验验证后定稿。

## 六 评测方案

### 6.1 基准与数据划分

- **GOAT-Bench。**
    - 场景来自 HM3D-Sem：145 个训练场景、36 个验证场景。val_seen、val_seen_synonyms、val_unseen 三个验证划分的区别在于目标类别，场景相同。
    - 测试集：val_unseen 每个场景的第一个 episode，共 36 个场景、278 个子任务，与 3D-Mem、HIMM、MetaNav 的报告口径可比。
    - 开发集：从训练场景中预留若干个，并与校准器训练数据隔离；val_seen 与测试集共用场景，不用作开发集。
- **A-EQA。** OpenEQA 的 557 道 HM3D 题同时用于 EM-EQA 与 A-EQA（63 个 HM3D 验证场景），官方主动评测子集为 184 题。
    - 测试：184 题，只在方法冻结后运行。
    - 开发：其余 373 题按 7 个问题类别分层抽取 canonical pilot fold；它与测试题场景重叠，需要在论文中说明。
    - 两种协议：逐题独立评测；同场景连续提问、记忆保留（参照 Sequential-EQA）。
- **可选的混合任务流分析。** 在 GOAT-Bench 与 A-EQA 重叠的场景中，把找物目标与问题串成同一个任务流，作为展示分析，不作为主结论。
- **SceneFun3D。** 没有对应的具身基准，列为局限。

### 6.2 指标

- GOAT-Bench：按目标模态（类别、语言描述、图片）与子任务序号分别报告成功率与 SPL。
- A-EQA：LLM-Match、LLM-SPL；连续协议下另报后续问题的导航代价。评分沿用研究二的 judge（`src/codex_agent/openeqa/judge.py`），并注明与官方 GPT-4 judge 的差异。
- 代价：每个任务的大模型调用次数、输入图像 token 数、墙钟时间。
- 机制指标：记忆命中率、同类错实例率、过早停止率、校准误差。

### 6.3 对比方法

下表为作者报告的参考数值。各方法的骨干模型与评测子集不同，不能直接横比；主结论只使用同骨干重跑的对照。

| 方法 | 骨干（原文） | GOAT-Bench SR / SPL | A-EQA LLM-Match / LLM-SPL | 备注 |
| --- | --- | --- | --- | --- |

### 6.4 证明研究一、二作用的消融

- 研究一的检索替换为 CLIP 匹配、3D-Mem 的预过滤，或由大模型直接从全部记忆中挑选。
- 去掉研究二的消歧与核验。
- 每个任务结束后清空记忆。
- 去掉核验结果写回。
- 决策方式对比：校准器、纯大模型决策、阈值规则。
- 自举迭代的轮数。
- 绘制性能与 token 随任务序号变化的曲线；预期研究一的收益随任务数增加而变大。

## 七 立题门槛（第 1–2 周）

对同骨干 3D-Mem 在开发集上的失败样本做分类：

| 失败类型 | 对应问题 | 对应研究内容 |
| --- | --- | --- |
| 从未观测到目标 | 探索 | 复用 frontier，不作为贡献 |
| 观测过但没有召回 | 检索 | 3.1 |
| 召回了错误实例 | 消歧 | 3.2 |
| 过早停止 | 核验 | 3.2 |
| 问答推理错误 | 推理 | 研究二 |

按各类占比分配后续精力。如果"未召回"和"召回错实例"的占比都很低，说明强大模型本身已能较好地认对实例，研究一、二的贡献会被稀释；此时把重心转向连续任务中的代价控制（token 与调用次数）和记忆复用。审计结果应作为开发记录归档。

## 十 风险与预案

| 风险 | 预案 |
| --- | --- |
| 方向活跃：MetaNav、EvoMemNav、HIMM、3D-Mem 都在这两个基准上做记忆 | 差异化落在"结构化关系检索 + 三维几何核验 + 可验证奖励的决策校准"，由立题门槛先验证 |
| 强大模型本身已很少认错实例 | 主论点转向代价与连续任务中的记忆复用 |
| Habitat 与 3D-Mem 工程延误 | 先保留 3D-Mem 的完整流程，只替换检索与决策模块 |
| 骨干与 judge 不一致 | 主结论只用同骨干、同 judge 的对照，论文数值单列 |
| 训练收益偏小 | 以校准误差和大模型调用次数下降为主要收益，如实报告 |
| 测试泄漏 | 开发集用预留训练场景；校准器只用训练场景数据；测试集只在方法冻结后运行 |
