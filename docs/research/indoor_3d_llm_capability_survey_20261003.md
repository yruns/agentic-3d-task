# 通用大模型在室内三维任务中的能力与适用边界

调研截至 2026 年 10 月 3 日。本文从已有能力证据重新比较室内三维任务，不预设导航是最佳方向。重点考察现成通用 LLM/VLM 在不进行大规模任务训练时能承担哪些工作，以及地图、几何工具、记忆或轻量适配在其中扮演什么角色。室外导航不在范围内；复杂操作只用于解释高层规划与实际执行的差别。

本文使用论文、正式会议论文集、作者代码和数据说明。报告中的数字均是相应来源的作者报告，不是本项目复现实验。对于 2026 年新近预印本，单独保留其版本和证据限制；检索日期不意味着所引用的每个实验都测试了当日最新模型。

## 一 怎样理解“比较擅长”

需要分开回答两个问题：一是大模型在系统中是否发挥了适合其能力的作用；二是完整任务是否已经可靠解决。能在正确候选中选择物体，不等于能从原始扫描中发现所有物体；能生成合理计划，不等于能在机器人执行失败后完成全部家务；能回答已看到的信息，不等于知道自己还没看到什么。

本文不把不同 benchmark 的百分比合成排行榜，而按以下证据判断：

- 通用模型或冻结模型能否直接提供有用结果，是否必须经过大量该任务训练。
- 与同信息条件下的直接提示、几何算法、相似度检索或专用方法相比，收益来自哪里。
- 实验给了哪些信息：真实候选、完整场景图、位姿、深度、参考路径、理想动作技能等。
- 结果衡量的是语言答案、对象选择、局部动作、整任务成功，还是人的偏好。
- 结论是否跨场景成立，以及样本数、分母和重复性是否足以支持判断。

### 大模型与三维信息有三种连接方式

| 连接方式 | 大模型真正接收什么 | 能证明什么 |
| --- | --- | --- |
| 通用视觉模型直接读图像或视频 | 当前视图、多视角图像、历史视频 | 模型利用可见证据理解环境的能力，仍需区分单视图语义与跨视图三维推理 |
| 通用模型使用三维工具 | 对象列表、几何测量、场景图、渲染视图和工具返回 | 语言解析、证据组织与工具决策能力；几何质量来自外部系统 |
| 经过三维任务训练的模型 | 点云 token、三维位置编码、专用视觉特征等 | 该模型在相应训练条件下的能力，不能直接归于通用 LLM 的零样本泛化 |

文中涉及视觉输入时通常指 VLM/MLLM。纯文本 LLM 若通过场景图或对象表工作，也可以参与真实三维任务，但它并没有因此直接从像素恢复完整几何。CLIP 式相似度模型和生成式大模型的贡献同样需要分开。

## 二 能力概览

**已有相对优势主要集中在开放语义与结构化决策：理解一个人想找什么、问什么、完成什么；把需求连接到可见证据、对象候选、空间约束和可调用工具。** 其中，证据充分的问答、给定候选的语言消歧，以及工具支持下的场景配置，比较适合使用通用模型起步。高层规划与主动观察也有用，但完整闭环的可靠程度更低。

下面的“相对优势”表示模型适合承担该环节，且有相应实验支持，不等于已经达到高成功率部署，也不是跨 benchmark 排名。证据和具体数字在后文展开。

| 室内三维任务 | 例子 | 大模型主要作用 | 当前判断 | 公共评价基础 |
| --- | --- | --- | --- | --- |
| 有证据的场景问答 | 某个房间有哪些物品、某物体位于什么位置 | 理解开放问题，检索和组合观察 | 相对优势较明确；证据覆盖与细节辨认仍限制答案 | OpenEQA、ScanQA、SQA3D |
| 自然语言目标定位 | 在多个候选中找到“桌旁背对门的椅子” | 属性、指代、参照物与关系组合 | 条件性适合；目标候选和几何工具很重要 | Nr3D、ScanRefer |
| 功能意图解析 | “开灯”对应找开关，“打开抽屉”对应把手 | 常识与任务语义连接 | 粗语义有优势；精确功能部件掩膜仍弱 | SceneFun3D、Fun3DU |
| 高层任务与技能规划 | 将日常需求转为有顺序的技能调用 | 子目标、对象参数、前置条件与反馈处理 | 明确对象/技能下有效；陌生视觉环境完整执行不稳定 | EAI、PARTNR、EmbodiedBench |
| 主动观察与取证 | 决定到哪个视点确认答案 | 问题条件化的证据选择 | 有进展；不能将理想视点访问等同自主移动 | Explore-EQA、OpenEQA A-EQA |
| 长期查询与连续找物 | 利用过去看到的物体，回答或再次访问 | 时间和目标条件检索、经验复用 | 有价值但尚不成熟；身份、过时事实和停止判断较难 | LA-EQA 的室内部分、GOAT、LangMap、LMEE |
| 语言约束场景生成 | 按用途、风格和关系要求构建三维房间 | 常识设计、资产选择、关系约束与迭代修订 | 工具系统层面的优势较明确；不是裸模型直接生成精确几何 | Holodeck、SceneSmith、SceneEval |
| 精确空间测量与视角转换 | 精确距离、跨视角身份、相机坐标变换 | 可解释任务并调用工具 | 不宜预设为通用模型的可靠强项 | VSI-Bench、Metric-Bench |
| 长程自主运动与操作 | 在未知房屋连续完成一整套任务 | 高层决策与反馈理解 | 仍明显依赖感知、执行器和状态维护 | R2R/RxR-CE、PARTNR、LongAct |

最关键的是任务形态，而不是是否贴了“3D”标签：输入一个完整物体表让 LLM 选 ID，与从连续 RGB 中自行建图、发现实例并移动到目标，是不同难度的任务。论文成绩应按实际接口解释。

## 三 场景问答、语言定位与功能理解

### 有证据的场景问答

OpenEQA 的历史问答适合评价通用 VLM 如何回答关于物体、属性、状态、位置和功能的开放问题；主动版本还要求获取观察。它的 LLM-Match 是语义评分，不是二元准确率。2024 年发布时的 GPT-4V 48.5、人类 85.9 是历史快照，本报告不将其作为今天最新模型的上限。[Meta 原始发布说明](https://ai.meta.com/blog/openeqa-embodied-question-answering-robotics-ar-glasses/)、[官方项目](https://open-eqa.github.io/)、[官方代码](https://github.com/facebookresearch/open-eqa)

较新的 CoV（ACL 2026 Findings）冻结模型，通过问题相关锚点和相机移动，在已有三维表示中渲染新视角。OpenEQA 表中，Qwen3-VL-Flash 从 52.65 提高到 59.82 个 LLM-Match 分；但增加了视角与调用，且表中实际评测数量未在本次核验中确认。它支持“改善证据可提升回答”，不能证明仅靠语言推理获得了完整三维认知。[论文](https://arxiv.org/html/2601.05172v1)、[代码](https://github.com/ziplab/CoV)

场景问答的相对优势在于理解不同问法、将可见事实与用途常识联系起来、整合分散观察。小物体、精确计数、跨房间关系及不存在的目标仍是问题。若一个问题只问当前图中的颜色，它主要检验二维视觉；场景级三维能力还需多视角身份与空间关系证据。

### 三维问答可以通过更好的输入组织改善

ScanQA 使用室内扫描与问题；SQA3D 加入关于提问者位置和朝向的语言情境。它们有训练集，许多 3D-LLM 成绩来自任务适配。CIDEr、Exact Match 和 LLM 评分含义不同，不能都称作“问答成功率”。[ScanQA](https://github.com/ATR-DBI/ScanQA)、[SQA3D](https://github.com/SilongYong/SQA3D)

KeyVT（ICML 2026）保持通用 VLM 冻结，利用相机几何及问题相关性组织视角，再压缩视觉 token。同 Qwen2.5-VL-7B，ScanQA CIDEr 为 63.4→69.6，SQA3D 表中 EM-1 为 46.0→50.4。但普通输入为 8 帧，KeyVT 先读 16 帧再压成 8 帧等效 token。更严格的同视角与 token 预算对照 FLoC→KeyVT，分别仅为 68.5→69.6、50.2→50.4。该方法不更新 VLM，但对每个输入的虚拟 token 做无监督数值优化，并需要访问内部 token。[论文](https://arxiv.org/html/2606.03100v2)、[实现](https://github.com/alivecat05/KeyVT)

这说明大模型的已有能力会受输入形式限制；也说明“增加视角”和“更有效压缩”必须通过不同对照归因。

### 给定候选的自然语言物体选择

例如“靠窗的桌子旁边、背对门的那把椅子”，要求解析目标、属性和参照物，再组合关系。Nr3D 的常见设置提供真值物体实例候选，目标保证在候选集中；ScanRefer 通常评价预测三维边界框与真值的 IoU，候选可能来自训练过的检测器。前者更适合隔离语义消歧，后者混合了感知和选择能力。[ReferIt3D](https://github.com/referit3d/referit3d)、[ScanRefer](https://daveredrum.github.io/ScanRefer/)

SeeGround（CVPR 2025）用冻结 Qwen2-VL-72B 结合渲染图、物体标记和空间描述。在相同 Nr3D 真值实例协议下，位置输入为 37.7%，图文融合为 43.3%，完整视角适配为 46.1%。这明确说明视觉呈现和语义关系结合有价值；但 Hard 子集为 38.3%，还不能称复杂多实例定位已可靠。[论文表2、3](https://arxiv.org/html/2412.04383v1)、[代码](https://github.com/iris0329/SeeGround)

Z3D（ACL 2026）进一步将通用二维定位、分割与几何提升连接，说明二维语义能力可以迁移到三维对象选择。不过它包含不同几何输入、候选来源及子集协议；部分组件接受过二维指代训练。不能把“没有三维任务训练”扩大成所有组件未经训练。[论文](https://arxiv.org/html/2602.03361v1)、[代码](https://github.com/col14m/z3d)

**能力判断：**在清晰候选和几何工具支持下，语言目标解析与候选消歧是适合冻结模型的任务。精确坐标、距离排序、可见性和实例检出应单独评估；候选里根本没有目标时，推理无法恢复完整端到端能力。

### 功能常识与细粒度部件定位

大模型可以从“打开抽屉”推断应关注把手，从“开灯”关联到开关；这比类别相似度检索更依赖功能语义。SceneFun3D 的任务却进一步要求在三维扫描中定位具体功能部件，而不只是说出类别。该评测提供既有高精度点云、带位姿的 RGB-D；下述系统还使用预训练视觉定位或分割器，不能理解为只凭普通 RGB 和语言模型完成全部三维感知。[任务规范](https://scenefun3d.github.io/documentation/benchmarks/task2/)

Fun3DU（CVPR 2025）用语言模型解析上下文物体和部件，再做多视角定位、分割与三维聚合，无任务特定微调。它在 30 个验证场景的 split0 上 mIoU 为 15.2、AP50 为 16.9。功能理解可以帮助选择目标，但掩膜质量仍有限。[论文](https://openaccess.thecvf.com/content/CVPR2025/papers/Corsetti_Functionality_Understanding_and_Segmentation_in_3D_Scenes_CVPR_2025_paper.pdf)、[代码](https://github.com/tev-fbk/fun3du)

UniFunc3D（2026 年 3 月预印本）使用冻结 Qwen3-VL 与 SAM3，加入视觉依据、局部高分辨率和时间窗口验证；其 30B 模型 split0 mIoU 为 24.30。该提升说明有进展，也说明不能将“理解该操作什么”与“准确找到小部件”合并成一个已成熟能力；更不能从部件掩膜推出真实可操作性、受力或关节运动能力。[论文](https://arxiv.org/html/2603.23478v1)

## 四 历史记忆、主动取证与连续找物

### 相关多视图组织能释放已有回答能力

3D-Mem（CVPR 2025）在同 GPT-4o 的 EM-EQA 比较中，约 3.1 张相关快照得到 57.2 分，约 3.0 张线性采样帧为 48.1。这是相近最终图像数量下的正向证据；但快照组织使用 RGB-D、位姿和三维对象结构，不能说整个预处理信息和计算预算完全相同。[论文](https://arxiv.org/html/2411.17735v5)、[代码](https://github.com/UMass-Embodied-AGI/3D-Mem)

这类方法适合回答“已观察场景中的某物体在哪里、有什么属性或与什么相关”。大模型负责问题理解、证据选择与答案组织，三维系统负责跨视图关联。3D-Mem 的 GPT-4o 分支冻结，LLaVA 分支经过任务训练；主动探索实验还依赖全局 navmesh/pathfinder，不能由问答增益顺便证明连续移动控制可靠。

### 主动选择观察已有进展

Explore-EQA 使用冻结 VLM 给问题相关的方向评分，融合进地图，配合校准后的停止策略；HM-EQA 包含 500 个问题、267 个 HM3D 场景。与非语义探索、CLIP 探索及组件对照相比，研究支持问题条件化的观察选择。但仿真采用理想里程计和无碰撞规划器，停止校准还使用标注集，因此结果不能直接解释成无任何支持的自主机器人能力。[论文](https://arxiv.org/html/2403.15941v2)、[代码](https://github.com/Stanford-ILIAD/explore-eqa)

“选择一个能看清的视点”与“真的移动到该视点”是两个实验层次。若把已有全局场景渲染、预录视点跳转和原子动作探索混为一谈，会高估大模型的具身能力。

### 跨时间查询有价值，但尚缺广泛证据

Mind Palace/LA-EQA（CoRL 2025）研究过去与现在的场景查询，说明时空检索能减少盲目加载历史。公开评测通过读取预录视点图像、更新位置 ID 并计算位姿间距离来模拟访问，不是连续避障执行。它有 150 个问题、5 个环境，且含部分室外视野问题；本报告将其作为方法参考，不用整体分数代表纯室内能力。[论文](https://arxiv.org/html/2507.12846v1)、[公开执行接口](https://github.com/mind-palace-laeqa/benchmark/blob/b127ddd6a67d96321486eb4cbf298c94cd716172/src/contextual_long_term_reasoning/belief_manager.py#L17)

因此，“昨天在哪里、现在是否还在”是有现实价值的应用形态，但必须有相应时间和实例证据。合理推测不能证明模型恢复了未被记录的搬运过程，也不能证明它预测了真实世界未来。

### 判断证据不足仍是明显弱项

AbstainEQA（CVPR 2026）包含各 1,636 条不可答和可答样本，并提供证据帧等资源。论文主表中 Gemini-2.5-Pro 的拒答召回为 42.79%，人类为 91.17%；这是该论文的模型快照和拒答指标，不是所有问题正确率。它说明模型容易把无法确认的问题当作可答问题，不能仅凭模型自己说“有把握”就验收。[论文](https://arxiv.org/html/2512.04597v1)、[数据与代码](https://github.com/gibrantaowu/AbstainEQA)

视觉缺失、语言指代不清、个人偏好和任务超出能力需要不同处理。更多图像只解决其中一部分。若研究主动核验，应同时测可答问题误拒答、不可答问题乱回答，以及获取新证据的实际代价；这是一项尚待改善的能力，不能归为大模型已经擅长。

### 连续目标搜索与记忆问答可以公开验收

GOAT-Bench 逐次提供类别、图像或语言目标，要求实际访问目标，适合验证连续找物与经验复用。LangMap 更强调房间、区域及实例语言；其同 RGB/Uni-NaVid 底层比较中，加入冻结记忆规划器后子目标 SR 从 34.4 提升到 42.8，SPL 从 15.0 到 18.1。这个增量有价值，但底层导航模型已经训练，42.8 也不是五个目标全部完成率。[GOAT](https://github.com/Ram81/goat-bench)、[LangMap](https://arxiv.org/html/2602.02220v3)

LMEE（CVPR 2026）进一步连接多目标探索与事后记忆问答，公开测试包含 166 个任务、828 个目标和 406 个问题。全量结果中，冻结 RA-Mem 为 20.46 目标导航 SR、55.17 选择题分；经过 GRPO 训练的 MemoryExplorer 为 22.05、64.78。其训练使用 8 张 H200，执行还调用 simulator pathfinder，因此高分不能归为通用模型本身的零样本移动能力。[论文](https://arxiv.org/html/2601.10744v2)、[代码](https://github.com/wangsen99/LMEE)

**能力判断：**语言条件的证据检索与回答是较明确的适配方向；主动看哪里、跨时间查什么已有进展；独立移动、完整连续任务和可靠证据充分性判断仍需更强支持。研究时应分别验收“找到答案”“找到物体”“走到目标”和“完成全部任务”。

## 五 高层任务规划与技能调用

### 已有相对优势

当对象、状态和可用技能表达清楚时，通用 LLM 可以把日常需求转成对象、子目标、顺序与工具参数，并根据执行反馈修改计划。这适合“将几件物品放到指定位置”“按条件整理某个空间”等语言组合任务。它要求系统检查对象是否存在、条件是否满足以及动作是否真正完成；常识不能替代当前场景事实。

### 符号规划与完整执行的差别

Embodied Agent Interface（NeurIPS 2024）在 BEHAVIOR 和 VirtualHome 上分别评价目标解释、子目标分解、动作排序及状态转移模型。其 2025 年论文版本中，o1-preview 在 BEHAVIOR 的动作排序 Task SR 为 81%，子目标分解为 60%；各环节单独测试时，其他部分由真值或规划工具补齐。这支持其作为高层语义模块的可用性，而不是视觉家务闭环的 81% 成功率。[原文表3与评测定义](https://arxiv.org/html/2410.07166v3)

PARTNR（ICLR 2025）提供更有解释力的同设置对照：验证集上的 decentralized ReAct，在部分观察与 oracle 技能下为 73% SR；改用学习技能为 57%；再使用 ConceptGraph 感知为 25%。这里的“部分观察”仍知道房屋布局。模型会规划与系统能完成，之间隔着感知与技能可靠性，不能把前者的成绩直接移到未知室内机器人。[PARTNR 表10](https://arxiv.org/html/2411.00081v1)

### 明确技能接口上的短任务更容易

EmbodiedBench（ICML 2025）的 EB-Habitat 中，Claude-3.5-Sonnet 在 Base 子集为 96%、Long 子集为 58%。默认有 10 个上下文示例、高层技能和文本执行反馈。这说明清楚的接口有助于完成短任务；不同难度子集并非只改变长度的严格因果实验，且默认是 few-shot。该研究中去掉图像后部分高层成绩仍接近，也提醒我们不能把全部收益解释成三维视觉理解。[原文表2与分析](https://arxiv.org/html/2502.09560v2)

### 2026 年的长程任务仍有明显缺口

LongAct/HoloMind（2026 年 5 月预印本）使用任务图、空间记忆、经验记忆、critic 和技能库，在 RGB-D 与语义分割支持下进行长程家务。Detailed split 中，同一 Qwen3-VL-32B 从直接模型的 6.14% 目标完成、0% 整任务成功，提高到系统的 51.2% 和 15%；GPT-5 配合系统为 59% 和 16%。这说明系统组织有效，也说明复杂整任务仍远未稳定。其跨 episode 经验需与独立任务零样本区分。[原文表1](https://arxiv.org/html/2605.14504v2)

**能力判断：**明确对象和技能上的高层语义规划是相对强项；未知环境中可靠完成长程家务目前仍是有待解决的问题。若选择这条方向，应把语义规划层与视觉闭环层分开评测，逐步替换真值状态和理想技能，观察性能损失来自哪里。

TEACh 还提供家务对话和任务执行的公共基础，可研究何时需要澄清。但人类对话数据、从历史对话续接和自主在线提问是不同设置；基准存在不等于当前通用模型已经擅长该能力。[TEACh 官方实现](https://github.com/alexa/teach)

## 六 语言驱动的室内场景生成与配置

这一方向与导航、问答不同：输入是房间用途、风格、物体及关系要求，输出是可渲染或可交互的三维室内环境。大模型主要提供语义设计、常识约束、工具调用和迭代修改；资产库、几何求解器与物理模拟负责形状和可行性。它是通用模型具备相对优势、且可以产生现实产物的一类任务。

### Holodeck 语义约束转化为三维布局

Holodeck（CVPR 2024）使用现成 GPT-4 选择房间、物体和空间关系，检索 3D 资产，再通过约束求解布置。与 ProcTHOR 使用相同资产来源的 120 对住宅场景比较中，64.4% 的整体偏好判断选择 Holodeck，23.3% 选择 ProcTHOR，另有平局。它支持“语言常识可改善场景配置”，不代表模型能直接精确生成坐标或符合所有物理条件。[正式论文](https://openaccess.thecvf.com/content/CVPR2024/papers/Yang_Holodeck_Language_Guided_Generation_of_3D_Embodied_AI_Environments_CVPR_2024_paper.pdf)

该系统没有为场景生成微调 GPT-4，但提示包含单个示例，因此应称“冻结通用模型的提示式生成”，不能把严格无示例的 zero-shot 与无参数训练混称。它使用资产检索和几何求解，也不是从零生成全部网格。[方法正文](https://arxiv.org/html/2312.09067v2)、[官方代码](https://github.com/allenai/Holodeck)

### SceneSmith 生成可供仿真使用的复杂场景

SceneSmith（ICML 2026）用现成 GPT-5.2 的设计、评审和组织角色，逐层生成建筑、家具和小物体，结合资产合成、检索与专门放置工具。论文在 210 条提示上评测，其中 179 条是房间、31 条是多房间；205 人参与偏好评测。[正式论文](https://proceedings.mlr.press/v306/pfaff26a.html)、[全文](https://arxiv.org/html/2602.09153v2)

179 个房间的作者报告包括 1.2% 碰撞率、95.6% 物体静态稳定率，以及独立的数量、属性和关系指标。稳定性来自 5 秒物理仿真，不能当作长期物理真实性或机器人任务成功率；其评测也包含 VLM 判断。该结果反映完整 Agent 与工具系统的能力，不是大模型裸输出坐标的能力。官方代码已公开。[实现](https://github.com/nepfaff/scenesmith)

**能力判断：**在资产和工具支持下，语言约束场景生成是值得认真考虑的强项。优势集中在“应该放什么、怎样符合用途与要求、如何组织修订”。精确碰撞、支撑和尺寸仍交给专门工具。相比再次做对象定位，它还能产出机器人训练环境、场景变体或交互式布局修改，研究任务本身具有不同形态。公开评价可从 SceneEval 的提示与指标、物理可行性检查及任务效用入手；不要只展示好看的渲染。

### 公共评价资源

SceneEval（WACV 2026）提供公开代码和 SceneEval-500：前 100 条为人工构建，另 400 条半自动生成。它评价数量、属性、对象关系、可达性、碰撞和越界等，部分指标调用 VLM，部分直接做几何计算。SceneSmith 使用的 210 条提示包含 SceneEval 子集和作者扩展，不等于完整 SceneEval-500。若选择这一研究方向，可以从现有资源开展比较，无需一开始自建全部评价体系。[官方代码与数据说明](https://github.com/3dlg-hcvc/SceneEval)

## 七 精确空间推理为何需要单独判断

### 不能把所有空间问题当成同一种能力

“沙发旁边可以放茶几”依赖语义常识；“图中这把椅子是否与另一视角的是同一把”依赖跨视角对应；“它距墙 0.37 米”依赖尺度恢复；“转身后目标在身体哪一侧”依赖坐标变换。模型在第一类问题上有用，不能推出它在其余三类都可靠。

VSI-Bench 以室内视频评价计数、距离、方向、房间尺寸、路线和出现顺序。原始研究发现，语言式 CoT 等推理提示并不普遍改善空间能力；显式认知地图对部分距离任务有帮助。这是任务条件下的实验结论，并非今天所有新模型的性能上限。[VSI-Bench 论文](https://arxiv.org/html/2412.14171v2)

### 2026 年进展仍需区分通用模型与空间适配

SpatioLM（ICML 2026）冻结底座并训练空间模块，项目页报告使用 20K 视频和 643K 空间问答。其同表 VSI-Bench 结果中，InternVL3.5-8B 从 56.1 提升到 65.0；在已经做过空间适配的 SenseNovaSI-8B 上为 68.7→71.6。它说明空间能力可以通过外挂模块改善，但不是无需空间训练的通用模型成绩，少参数也不等于少数据。[作者方法与实验](https://xiaomi-research.github.io/spatio-lm/)

这些结果还体现不同任务的不均衡：较高的总分不能保证路线推理、视角变换或精确度量同样可靠。VSI-Bench 混合选择题与数值容差评价，不应将总分解释为一个通用的“空间理解正确率”，更不能等同机器人执行成功率。

Metric-Bench（2026 年 9 月预印本）进一步用 ScanNet 的室内图像，在给定参考物体真实尺度后询问目标尺寸、位置、距离等；它包含独立场景的 1,340 条测试问答。作者的 Qwen3-VL-32B 得到 39.24 MRA，而专门强化微调的 MetricReasoner 为 48.59；MRA 是多种相对误差阈值的平均指标，不是精确测量成功率。API 模型和人类仅测 400 条子集，不能与全量结果直接比较。[定义与结果](https://arxiv.org/html/2609.25841v1)

**能力判断：**精确三维定位、尺度与跨视角变换不宜作为通用 LLM 已有强项来立题。更符合当前证据的方案是让它解释任务、选择几何工具并组合计算结果。若研究模型本体的空间能力，需要明确接受空间数据、适配训练与独立诊断评测。

### 榜单高分还需排除语言捷径

VSI-Bench 后续审计表明，部分空间题可被非视觉模式利用。因此，一个系统是否真的理解了当前房间，至少需要无图像、错场景、对象名称替换和几何关系扰动等对照，而不只检查回答是否流畅。相关工作中的测试集交叉验证用于审计基准偏差，不是允许研究方法在测试数据上训练。[偏差审计论文](https://arxiv.org/html/2511.04655v1)

官方数据卡在 2026 年 8 月进一步注明，当前公开 Debiased v1 是人工参与、按题型过滤的先导版本，并非自动 IBP 算法生成。使用时应锁定实际数据版本，不能把论文流程与下载到的子集混为一谈。[官方数据说明](https://huggingface.co/datasets/nyu-visionx/VSI-Bench)

MMSI-Bench 的跨图像匹配、视角转换和空间逻辑分类可帮助做错误分析，但该基准混有室内、驾驶等来源，本报告不将其整体分数用作室内能力结论。它 2025 年版本的模型成绩也不能冒充截至本次日期的最新模型上限。[MMSI-Bench](https://arxiv.org/html/2505.23764v2)

## 八 跨任务比较与研究选择

### 哪些任务更能利用通用大模型的优势

综合文献，较合适的任务通常有三个共同点：输入能被组织成可核验的视觉或结构化证据；输出以语义选择、关系约束、计划或工具调用为主；精确几何计算与动作执行有专门机制支撑。这是根据多类实验归纳的设计判断，不是一个跨基准统计排名。

因此，选择研究课题时，应首先问大模型是否必须理解开放语言、组合常识和比较多个条件。若任务只需按已知坐标求最短路径，或只需在六种物体类别中选择最近的探索边界，就需要证明大模型比简单算法带来的实际增量。反过来，若只根据常识就能猜对答案，也不足以证明模型理解了当前三维场景。

### 研究三的任务升级与推荐方向

根据已确定的论文分工，QA、Nr3D、SceneFun3D 等场景理解、定位与功能识别任务已由研究二覆盖，不再作为研究三的主要评价任务。研究三应以完整任务的环境状态达成为目标，研究在部分观察、动作失败及多阶段依赖下如何持续决策。是否直接复用研究二代码由实现条件决定，不要求强行绑定。

**推荐任务：自然语言驱动的室内长程具身任务执行。** 可暂用研究点标题“基于大模型的室内长程任务规划与执行方法研究”。典型任务是把多个物体整理到指定房间或容器，满足位置、顺序和角色能力约束；若某个前置条件不成立，需要补充观察、执行准备动作或重新规划，最后由环境评价器核验。

例如，任务要求将杯子先送到水槽清洗，再收入柜子，同时把书放回书架，并在需要时与具有不同技能的伙伴分工。这是任务形态示意；具体实验使用公开 episode 与评价器。系统不仅需要找到杯子和把手，还要判断当前状态、协调动作顺序、确认执行结果，并防止后续行动破坏已完成条件。PARTNR 中已有同一物体多次重排、空间条件和异构角色任务。[PARTNR 任务定义](https://arxiv.org/html/2411.00081v1)

| 维度 | 研究二覆盖的基础能力 | 研究三新增的评价要求 |
| --- | --- | --- |
| 输出 | 答案、对象、功能区域或关系 | 能执行并持续调整的行动序列 |
| 环境 | 理解当前场景及其证据 | 行动改变位置、容器、设备或其他任务状态 |
| 推理跨度 | 解决当前查询或定位条件 | 维护多个目标的依赖，处理前置条件与后续影响 |
| 错误处理 | 改善单次判断 | 发现执行偏差，恢复任务进程并避免重复失效 |
| 完成标准 | 问答、定位或分割指标 | 整任务成功、目标条件满足及过程约束合规 |

### 三种具有足够挑战性的任务形态

| 方向 | 核心能力 | 公开评价与定位 | 推荐程度 |
| --- | --- | --- | --- |
| 室内多目标整理与状态改变 | 多物体、跨房间、开闭取放、顺序约束和执行反馈 | PARTNR 主评测；EB-Habitat 作高层规划迁移；ALFRED 可作更严格视觉执行验证 | 主推荐，难度与冻结大模型路线较匹配 |
| 人机或多机器人协作任务完成 | 任务分工、能力差异、伙伴进度、共享对象和等待条件 | PARTNR 原生协作；TEACh 的 TATC 可用于在线对话协作 | 高挑战的扩展，需将伙伴行为和反馈权限纳入实验 |
| 更全面的家庭活动执行 | 清洁、烹饪、整理等多种物理状态变化 | BEHAVIOR-1K；2026 原生挑战包含100任务、7场景 | 通用性更高，但物理执行与低层技能负担也显著增加 |

任务生成或场景编辑仍是独立室内三维方向，但若希望保持具身应用与真实状态改变，以上任务比静态查询更符合本次研究三要求。这里的通用性应通过未见目标组合、场景和任务类型来量化，不能仅以一个自由文本输入框作为依据。

### 基准选择与实际接口

**PARTNR 优先作为主基准。** 官方公开 planner、工具、评测代码、train/val 数据和可固定使用的导航/抓取/放置技能 checkpoint，能够接冻结 API 或本地模型。主实验选择一种观察和技能配置，各方法使用相同权限，再用其他配置检验执行误差下的鲁棒性。本次公开数据目录未看到 test 文件，因此不承诺立即复现隐藏测试。[官方实现](https://github.com/facebookresearch/partnr-planner)、[公开数据](https://huggingface.co/datasets/ai-habitat/partnr_episodes/tree/main/v0_0)

需要明确 PARTNR 的原生角色限制：其官方 single-agent 配置额外赋予清洗、注水、倒水等能力，并不只是关闭伙伴。保留原生协作任务时，可以固定伙伴策略，仅研究目标 agent 的规划；若研究单体，需要明确技能集合及可完成的任务子集，并单列结果。[单体配置](https://github.com/facebookresearch/partnr-planner/blob/main/habitat_llm/conf/baselines/single_agent_zero_shot_react_summary.yaml)

若选择在线语言交互扩展，应使用 TEACh 的 TATC 协议；EDH/TfD 主要读取已有对话。TATC 的 Commander 可以搜索物体并检查进度，具有比执行者更强的信息权限。比较方法时应固定伙伴及权限，不能将伙伴提供的信息说成执行者自行感知所得。[TATC 官方接口](https://github.com/GLAMOR-USC/teach_tatc#note-about-model-io)

**EB-Habitat 适合作为高层规划的第二验证。** 它使用室内三维画面、参数化技能与随行动变化的状态，但公开配置采用 kinematic 模式、关闭物理步进、限制30个高层步，并在目标满足后自动结束。因此它不验证接触物理或 STOP 判断。长程数据已有修订，应固定版本并重跑基线。若要求更严格的跨模拟器视觉闭环，可选择原生 ALFRED 并固定一个现成感知与执行栈，但环境维护成本更高。[EB-Habitat 配置](https://github.com/EmbodiedBench/EmbodiedBench/blob/master/embodiedbench/envs/eb_habitat/config/task/language_rearrangement.yaml)、[ALFRED](https://github.com/askforalfred/alfred)

**BEHAVIOR-1K 不宜在起步阶段默认承担完整物理挑战。** 2026 官方赛道采用 RGB、深度和本体感知，包含100个完整任务；框架中的 symbolic action primitives 则可直接改变物体状态或位置。高层符号执行、带辅助抓取的运动规划与原生视觉物理赛道是不同设置，应分别报告。可以将它作为已有稳定执行器后的增强验证。[2026 官方挑战](https://behavior.stanford.edu/challenge/index.html)、[动作原语源码](https://github.com/StanfordVL/BEHAVIOR-1K/blob/main/OmniGibson/omnigibson/action_primitives/symbolic_semantic_action_primitives.py)

### 能体现研究工作量的方法问题

研究应落在“部分观察与执行反馈下，如何把自然语言目标持续转化为可执行决策”。可围绕下列问题选择一个核心机制，而不是同时堆叠所有模块：

- **任务相关状态维护**：哪些对象、状态和关系会影响后续动作，哪些已完成条件可能因新动作或伙伴行为而失效。
- **依赖与执行规划**：如何检查前置条件，安排互相依赖的子任务，并依据执行结果局部修改计划。
- **验证与恢复决策**：何时需要重新观察、重试、换目标或重新分工，以及如何核验最终条件。

这些问题允许冻结通用 LLM/VLM，复用固定技能，必要时只训练一个状态变更检查器、子目标可执行性模型或重规划触发器。若更新了该模块，实验需明确为轻量任务适配；冻结大模型不意味着所有低层组件未受过训练。

方法贡献可以由失败轨迹分析、结构化状态或决策机制、小模块训练、固定条件消融、跨任务迁移及完整终态评价共同支撑。主要指标保留官方整任务成功和目标满足度，再补充约束违规、恢复后的成功率、重复动作与模型调用成本。自定义扰动与原协议主结果分表，不用“回答如何执行”代替真实执行。

### 近邻与尚不能依赖的资源

LongAct/HoloMind（2026）已经组合 DAG、空间记忆、经验、critic 与技能恢复，因此“分层规划＋记忆＋反思”本身不是充分创新。其论文报告的长程难度很贴本题，但本次尚未核实完整官方任务、代码和评测入口，不宜成为唯一实验依赖。[LongAct](https://arxiv.org/html/2605.14504v2)

ADAPT/DynAfford（ACL 2026）进一步研究未明示的动作适用条件，例如先处理脏污或占用，再继续完成原任务。它已覆盖适用性判断与暂缓不可行目标，因而“检查前置条件后重规划”也需要更具体的差异。本次官方仓库仍说明完整代码、数据和评价流程待发布，现阶段列为重要近邻，不作为确定可运行的主基准。[正式论文](https://aclanthology.org/2026.acl-long.1109/)、[官方发布状态](https://github.com/charlotteannchen/ADAPT-Codebase)

WorldLines 和 RoboGraph 的任务状态研究有方法参考价值，但前者主要评价结构化历史上的问答与计划，后者的主体为符号状态图，视觉实验主要是两个桌面任务。它们不能替代本题要求的完整室内视觉具身任务主评测，也不应仅因名称含“长程”就提高优先级。[WorldLines](https://arxiv.org/html/2606.18847v1)、[RoboGraph](https://arxiv.org/html/2608.08036v1)

### 判断一个方法是否真正用到了三维场景

建议统一保留以下几类对照：

| 对照 | 排除的问题 |
| --- | --- |
| 不给图像或替换为其他房间的图像 | 答案来自语言先验而非当前场景 |
| 只给对象类别，再给属性、关系与几何 | 增益究竟来自开放语言理解还是额外真值信息 |
| 真值候选与真实检测候选分开 | 模型选得对，但系统找不到目标 |
| 几何算法或图文相似度基线 | 复杂 Agent 是否只是替代了简单规则 |
| 同一 VLM、同样证据、同样预算 | 提升是否只是模型更强、看得更多或调用更久 |
| 只报告子步骤与完整任务分别统计 | 局部判断正确是否能持续转化成最终完成 |
| 可回答、证据不足、目标不存在分别统计 | 只在可解任务上好看，却在实际问题上过度自信 |

对于小模块训练，还需分别披露预训练底座、更新参数、训练数据、教师生成、交互采样和全部计算成本。对闭源模型可以训练外部检索/验证模块；对开放模型可以考虑轻量适配，但两者不能都简称“零样本”。

## 九 建议的阅读路径与证据使用

先阅读各任务的定义和评价方式，再阅读强方法与失败诊断。问答重点比较 OpenEQA、ScanQA、SQA3D；指代定位重点辨别 NR3D/ScanRefer 的候选与检测权限；连续任务分别阅读 GOAT、LangMap 和 PARTNR；生成方向阅读 Holodeck、SceneSmith 与 SceneEval；精确空间能力用 VSI-Bench、Metric-Bench 等作专门诊断。

数值只在同任务、同划分、同输入与同评价器下比较。CIDEr 不等于答案正确率；LLM judge 的归一化分数不等于任务成功率；目标完成比例不等于整条多阶段任务成功；人的偏好不等于物理正确。使用有日期的榜单和版本化论文，避免把较老模型结果当作今日所有大模型的上限。

本报告核验公开证据，没有运行上述模型或评测。文件中的应用建议属于研究判断；新的 benchmark、预印本与有限规模实验均按其实际证据范围使用。
