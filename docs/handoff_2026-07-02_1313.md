## Project Overview

This repository implements agentic 3D scene-understanding workflows and
benchmarks. The current workstream is centered on Codex Agent SDK runners for
NR3D, OpenEQA, and SceneFunc3D, using a project-local ModelHub adapter and
repo-defined tool/skill workflows. SceneFunc3D currently uses a MolmoPoint +
SAM2.1 sidecar to point at a task-conditioned affordance in RGB frames, generate
SAM masks, lift masks into 3D, fuse accepted fragments, and score final raw mesh
point ids against hidden SceneFunc3D annotations.

The highest-priority state is SceneFunc3D benchmark reliability. Raw point-id
alignment is fixed for completed samples, but the agent loop is not yet
benchmark-stable: many cases fail through ModelHub encrypted reasoning state
handling, and successful cases still have low IoU due to semantic/affordance
selection and multi-view policy weaknesses.

## SceneFunc3D Interpretation

Raw/source mesh point-id alignment is fixed for completed samples. Completed
predictions contain `point_indices` in the raw `data/SceneFun3D/<visit>/raw`
mesh vertex-id space, and scorer validation rejects ids outside the raw mesh
range. Low IoU is therefore not currently explained by conceptgraph-to-raw id
mismatch.

The completed-case quality issue is mostly semantic and policy-level:

- `55b56254` is the best case, IoU `0.475806`, and fused two compact nightstand
  bottom-drawer knob fragments.
- `c9cde8d0` is strong numerically, IoU `0.317919`, but should still be visually
  checked for overlay-to-depth behavior.
- `71e753ae`, `a1574eea`, and `af0b7790` show the pipeline can find compact
  knobs but is sensitive to row/ordinal ambiguity.
- Zero-IoU completed cases are semantic misses: `609f3c02` selected a visible
  cord/plug-like region for an occluded unplug affordance, `9773cbd7` and
  `bd171354` hit drawer ordinal/instance mismatches, and `f57e5506` likely hit
  lamp switch affordance ambiguity.
- Very low nonzero cases include broad over-selection, especially broad
  window/blinds panels for small `hook_turn` affordances.

## Known Risks

| Risk | Severity | Mitigation |
|---|---|---|
| ModelHub `invalid_encrypted_content` breaks SceneFunc3D turns early. | High | Add redacted adapter diagnostics for `chat_run_id`, selected upstream alias/key alias, status, and log id; make continuation requests sticky to the first successful upstream for that `chat_run_id`. |
| Free-form agent loop spends most time in reasoning/orchestration and can build malformed long JSON. | High | Move deterministic tool sequence into runner-side state machine or typed helper commands; reserve model calls for target choice and accept/reject decisions. |
| SceneFunc3D successful masks have low IoU even after raw-id alignment. | High | Add affordance-size priors, SAM compactness scoring, drawer ordinal validation, and raw-id cluster consistency checks across views. |
| Failed SceneFunc3D turns previously lacked first-class `run_home` in failure rows. | Medium | Preserve `CODEX_AGENT_KEEP_RUN_HOME=1` for diagnostics and record run-home metadata directly in batch failure artifacts. |

## Potential Problems

- **Problem**: assuming low IoU means point-space mismatch.
  - **Impact**: wastes time re-debugging an already fixed raw-id path.
  - **Suggested Fix**: first inspect `fused/mask_data.npz:point_indices` and
    raw mesh range validation. The latest all-`421254` completed cases had zero
    raw-id violations.

- **Problem**: rerunning SceneFunc3D without the local adapter preflight.
  - **Impact**: Codex turns fail before useful tool work.
  - **Suggested Fix**: run `curl -sf http://127.0.0.1:8787/health`. If down,
    start `python3 -m uvicorn adapter.app:app --host 127.0.0.1 --port 8787`
    inside `codex_modelhub_adapter`, preferably in `tmux` for long runs.

- **Problem**: restoring fallback behavior for encrypted reasoning state.
  - **Impact**: can silently drop required context and reduce prompt-cache
    continuity, recreating earlier NR3D quality/cache regressions.
  - **Suggested Fix**: fail closed and fix upstream affinity instead.

- **Problem**: remote SAM mask output path is treated as local.
  - **Impact**: client cannot load masks because remote server and client are
    not on the same machine.
  - **Suggested Fix**: keep mask transfer by value, such as RLE/base64 payloads,
    and materialize on the client under allowed output roots.

- **Problem**: committing real sidecar headers or ModelHub credentials.
  - **Impact**: credential leak.
  - **Suggested Fix**: use gitignored `configs/scenefunc3d_backends.toml` and
    `configs/scenefunc3d_sidecar_headers.toml`; track only `.example.toml`
    templates.

## Suggested Solutions

- Start with adapter diagnostics. Without fixing `invalid_encrypted_content`,
  SceneFunc3D batch metrics will remain dominated by transport/state failures.
- After adapter stability, reduce agent-loop freedom. The measured cost profile
  shows that optimizing Molmo/SAM alone will not materially improve case
  duration; deterministic orchestration is the bigger win.
- Preserve the current raw-id validation invariants. Any new mask path should
  still emit raw/source mesh `point_indices` and validate against
  `raw/mesh.ply` vertex count.
- For quality, add action-aware and geometry-aware validators before final fuse:
  broad masks are suspicious for `hook_turn`, `pinch_pull`, `tip_push`, and
  `key_press`; drawer tasks need explicit ordinal/side/row checks.
- Keep NR3D v8/v11 as regression gates for adapter changes. A SceneFunc3D fix
  that breaks NR3D cache, reasoning summary carryover, or encrypted-state
  semantics is not acceptable.
