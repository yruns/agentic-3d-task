## 2. Infrastructure & Gateway Resilience Fixes Supporting Full-Scale Evaluation

During the initial launch of `v16`, 559 episodes suffered mid-turn `409 Conflict` aborts caused by transient upstream disconnects on `gemini_chat` multi-step tool sessions, and were erroneously marked `status = "completed"` when `EpisodeExecutor` fell back to synthetic completion. Three structural fixes were implemented and verified before cleaning all 559 contaminated episodes and re-running them to completion:

1. **Pre-Commit Lease Rejection & Transient Upstream Retries (`src/codex_adapter/application/gateway.py`):**
   - For `gemini_chat`, upstream state is carried entirely by the client and only persisted locally upon `self.store.commit()`. Pre-commit transport/conversion errors (`429, 500, 502, 503, 504`, `RemoteProtocolError`, `ReadTimeout`) now call `self.store.reject(lease)` instead of `self.store.indeterminate(lease)`, eliminating permanent `409 Conflict` session self-locking.
   - Added gateway-internal exponential backoff retries (`upstream_max_retries = 3`, `upstream_retry_backoff_seconds = 1.5`) and inflight request deduplication/abandonment tracking (`abandon_request()`).
2. **Elimination of False `"completed"` Fallback on Interrupted Turns (`src/codex_agent/alfred/execution.py`):**
   - When a turn is interrupted without `finish_episode`, `EpisodeExecutor.run()` now records `status = "incomplete"` rather than synthesizing `status = "completed"`, and retries up to `max_turn_continuations = 2` with full `completed_macros` and `recent_tool_calls` context.
3. **11-Slot Multi-GPU Perception Pool & 84-Worker Dual-Display Evaluation (`src/codex_agent/alfred/perception_server.py`, `alfred_runner.py`):**
   - Scaled `ScenePerceptionServer` to 11 persistent worker slots across physical GPUs `0, 0, 2, 2, 3, 3, 4, 5, 5, 6, 6` (strictly excluding physical GPU 1) with per-slot lock files.
   - Coordinated 84 concurrent evaluation workers (42 forward workers on display `:5` + 42 reverse workers on display `:6`) via non-blocking per-episode flock (`episodes/.{idx:04d}.lock`) and atomic disk checkpoint synchronization (`_sync_disk_attempts`).

## 4. Deep-Dive Failure Analysis & Direct Alignment with Thesis Point 1.2.3

Across the **1,239 failed episodes** in `v16`, full trajectory and tool-call audits reveal four systemic bottlenecks that directly validate **Thesis Research Point 1.2.3** (*"基于增量场景记忆的大模型具身任务执行方法研究：面向未知环境的增量式场景记忆构建 + 闭环策略程序生成与执行验证"*):

### 4.1 Bottleneck 1: Premature `finish_episode` Without Post-Condition Verification (`55.29%` False Completion Rate)
- Out of **1,239 failed episodes**, **685 episodes (`55.29%`)** ended via `policy_stop`—meaning the agent explicitly invoked `finish_episode` claiming the task was complete, yet the official PDDL evaluator scored `success = False`!
- **Root causes of false completion:**
  1. **Finishing while still holding the target object** instead of placing it on the destination receptacle (especially in `pick_cool_then_place_in_recep`, `pick_heat_then_place_in_recep`, and `pick_clean_then_place_in_recep` when the natural-language prompt omits the final counter/table or after retrieving the item from an appliance).
  2. **Finishing `pick_two_obj_and_place` after placing only 1 object** (yielding `GC = 1/2`, `SR = 0`).
  3. **Finishing `pick_and_place_with_movable_recep` after placing the small object into the `Pot`/`Pan`/`Bowl`/`Plate`/`Cup` without moving the movable receptacle to the target surface** (or vice versa, moving the empty receptacle without putting the content inside first).
  4. **Finishing state-change tasks (`clean`/`heat`/`cool`/`slice`) without actually completing the state transition** on the placed object.

### 4.2 Bottleneck 2: Interaction Readiness Gap (`PutObject: No valid positions`, Closed Containers, & Close-Range Mask Loss)
- Reaching an FMM navigation stance (`navigate_to`) does not guarantee interaction readiness:
  - `PutObject: No valid positions to place object found` is the single largest simulator primitive failure (**645+ occurrences**), caused by feeding full-surface or cluttered receptacle masks to AI2-THOR's `PutObject` or standing at suboptimal pitches/distances.
  - `PutObject: Target openable Receptacle is CLOSED` (**145+ occurrences**) and `no detection mask in current view after framing` (**36.2% of episodes**), especially when standing too close to large doors (`Fridge`, `Cabinet`, `Microwave`) or looking at small items inside receptacles (`SinkBasin`, `Fridge`).

### 4.3 Bottleneck 3: Multi-View Category Drift & Container–Content Mask Adhesion
- **91.5% of episodes** exhibit open-vocabulary 2D detector category drift across views (e.g., `Egg -> Apple`, `Fridge -> Cabinet`, `Spatula -> ButterKnife`, `Faucet -> DeskLamp`, `Candle -> TissueBox`).
- When an item is placed inside a `SinkBasin`, `Fridge`, or `Microwave`, or when a container is opened, child objects inside the container frequently adhere to the parent mask or lack explicit `parent_receptacle_id` / `contained_object_ids` topology in `IncrementalSceneMemory`.

### 4.4 Bottleneck 4: Single-Step Tool Call Overhead (`38%–49%` Zero-Action Queries)
- When the agent orchestrates tasks via isolated atomic tool calls (`list_objects` $\rightarrow$ `navigate_to` $\rightarrow$ `view_crop` $\rightarrow$ `interact_object` $\rightarrow$ `list_objects` on failure), nearly half of the 35-decision budget is consumed by zero-action queries and manual candidate switching.

## 5. Architectural Design for v17: Guarded Subgoal Policy Programs & Pre-Commit Verifier

Rather than having the LLM write raw, unconstrained Python loops (which suffer from open-loop runaway when object IDs split/merge, lose VLM visual disambiguation inside the loop, and waste turns on syntax/attribute errors), **v17 implements a two-layer Guarded Subgoal Policy Program architecture**:

1. **Enriched Incremental Scene Memory (`IncrementalSceneMemory` & `ObjectMemory`):**
   - **Multi-View Category Stability Metrics (`evidence_confidence`, `is_stable`, `top_alternatives`)**: Explicitly quantify label stability from multi-frame votes so ambiguous candidates are flagged before interaction.
   - **Explicit Object State Ledger (`sliced`, `cleaned`, `heated`, `cooled`, `toggled_on`, `open`) & Container–Content Topology (`parent_receptacle_id`, `contained_object_ids`)**: Track verified state transitions and spatial containment across `PutObject`, `PickupObject`, `OpenObject`, `SliceObject`, and compound appliance macros.
2. **Closed-Loop Guarded Subgoal Policy Program Interpreter (`execute_subgoal_program`):**
   - Allows Codex to submit a structured, declarative subgoal policy block (`acquire_target`, `place_held_into_receptacle`, `process_in_appliance`, `slice_target`, `illuminate_held_object`, `transfer_with_movable_receptacle`) with target category/ID specifications, automatic precondition handling (e.g. auto-opening closed containers, auto-unloading occupied hands), multi-pitch/multi-stance framing, automatic 3D sibling candidate fallback on disqualifying errors (`CanPickup`, `NOT a receptacle`, `No valid positions`, `Bad interact mask`), and postcondition verification—executing a full closed-loop subgoal in **1 decision turn**.
3. **Pre-Commit Goal Predicate Verifier on `finish_episode` (`verify_task_goal`):**
   - Inspects the episode's goal structure and current `IncrementalSceneMemory` state ledger when `finish_episode` is called.
   - Rejects premature completion (`status = "verification_failed"`, `finish_requested = False`) with actionable diagnostics whenever:
     - the agent is still holding an object on a placement/clean/heat/cool/movable-receptacle task (or NOT holding an object on an examine-in-light task);
     - a required state transition (`cleaned`, `heated`, `cooled`, `sliced`, `toggled_on`) has not been recorded in the ledger;
     - a `two_obj` task has only placed 1 item on the target receptacle category;
     - a `movable_recep` task has not placed the content inside the movable receptacle AND placed the movable receptacle onto the destination surface.
