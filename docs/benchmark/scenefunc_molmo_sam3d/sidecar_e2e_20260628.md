# SceneFunc MolmoPoint SAM2.1 sidecar E2E status, 2026-06-28

This record covers the repo-integrated sidecar path for the SceneFuncVal-CG
agent task:

```text
agent visual evidence
-> MolmoPoint-8B point prompt
-> agent approves point overlay
-> SAM2.1-Hiera-L mask candidates
-> agent approves contact sheet candidate
-> 2D mask to 3D fragment
-> final mask artifact
```

## Code Status

- Branch: `feat/scenefunc3d-agent-tools`
- Base: `21dc4a16ac361a474d8d119c6e44f664c4c2b050`
- Current implementation includes local HTTP sidecar clients, Molmo and SAM
  sidecar servers, deterministic 3D lifting, agent-visible artifacts, approval
  state, and a single-case runner.
- The runner now rejects fake final answers: final artifact JSON, `points_world`
  NPZ, ASCII PLY vertex counts, accepted fragment ids, and selected frame ids
  are validated before `result.json` is written.
- The final mask NPZ now carries scene `point_indices`; the scorer can read
  runner `result.json`, resolve `mask_artifact_path`, load hidden annotation
  indices, and compute IoU/precision/recall/F1.
- `python -m codex_agent.scenefunc3d.evaluation` scores a written
  `result.json`. The runner also supports `--score`, so a single-case run can
  write `result.json` and print metrics in one command.
- The agent tool loop now includes real `inspect_mask_artifact`,
  `suggest_additional_views`, and `fuse_accepted_masks` dispatch paths.
  `view_frame` exposes available depth, intrinsics, and pose paths for direct
  lifting, and `keyframe_selector` is frame-id/query aware with an explicit
  coverage-fallback strategy instead of returning the first K frames silently.
- `molmo_point` persists raw text but fails recoverably if Molmo returns no
  structured `<point>` tags, so SAM cannot run from an empty point prompt.
- The first sidecar implementation used the wrong real-model assumption for
  both heavy models: Molmo server followed old `Molmo-7B-D` style generation,
  while the available `MolmoPoint-8B` snapshot requires
  `AutoModelForImageTextToText`; SAM server followed official
  `facebookresearch/sam2` `.pt + yaml`, while the available Hiera-L cache is a
  Hugging Face `model.safetensors/config.json` snapshot.

Intermediate failures found and fixed:

- MolmoPoint-8B does not emit legacy `<point x="..." y="...">` tags. The
  server now uses Molmo remote code `extract_image_points(...)`, returns
  structured `image_points`, keeps the raw text unchanged, and the client only
  falls back to legacy raw-text parsing if no structured image points exist.
- The Molmo label parser must tolerate `>` characters inside quoted
  `coords="..."`. The parser now ignores delimiters inside quoted attributes
  and bounds-checks extracted image points against the input image dimensions.
- SAM2.1-Hiera-L transformers input tensors needed BF16 alignment: the server
  casts `pixel_values` to the model dtype before inference.
- SAM2.1-Hiera-L transformers output scores can also be BF16. The server now
  casts `iou_scores` to float32 before CPU/NumPy conversion.
- Real SAM masks commonly include some pixels whose depth is zero or invalid.
  3D lifting now back-projects the finite positive-depth subset and still fails
  with `lift_too_sparse` if the accepted mask has no valid-depth pixels.

## Current Assessment

The repo path is substantially closer to an evaluable SceneFunc3D task, but the
goal is not complete. The real `MolmoPoint-8B + SAM2.1-Hiera-L` sidecar tool
chain now runs on an H100 worker for one fixed frame, writes agent-visible
Molmo/SAM review artifacts, lifts one accepted candidate, and fuses a 401-point
3D mask artifact. True completion still requires the full agent runner to use
these tools in the intended multi-view loop, make view-supplementation
decisions after the first lift, write the final SceneFunc3D `result.json`, and
score that output against the benchmark annotation.
