# OpenEQA v3 — first full ScanNet split, evidence-seeking tools + BEV, 2026-06-12

First **full-set** OpenEQA evaluation in `agentic-3d-task` (v1/v2 were n=10
smokes). Runs the entire **ScanNet split — 1,079 questions across all 89 local
scenes** — with the evidence-seeking tool loop (`--tools`) and the mesh-free
schematic BEV.

## Headline

**MNAS = 73.96** over all 1,079 ScanNet questions. **Completion 1,079/1,079
(100 %)**, 0 unresolved failures. Prompt-cache hit rate 0.939 (mean cache ratio
0.498).

Judge-score histogram (1–5): `1:155  2:20  3:129  4:186  5:589` (54.6 % perfect

## Scope (why 1,079 and not 1,636)

`open-eqa-v0.json` has 1,636 questions: 1,079 `scannet-v0` + 557 `hm3d-v0`. Only
the prepared **ScanNet** assets are present locally (`data/OpenEQA/scannet/`, 89
scenes); there are **no hm3d assets**. `filter_questions_with_local_scenes`
drops the 557 hm3d questions automatically, so "full" here = the complete
ScanNet split (all 89 scenes, all 1,079 questions). The hm3d split is out of
scope until those scenes are prepared.

## Exact invocation

Main pass (30 workers):

```bash
source .venv/bin/activate
PYTHONPATH=src python -m codex_agent.cli.run_openeqa \
  --questions data/open-eqa-v0.json \
  --data-root data/OpenEQA/scannet \
  --output-dir tmp/openeqa_eval_v3_tools_full1079_20260612 \
  --num-frames 8 --workers 30 --tools
```

Recovery pass (6 questions that hit a sticky `429` failure under 30-worker
contention; their `status=failed` checkpoints were deleted and re-run at low
concurrency, which is safe because the runner skips already-checkpointed
questions):

```bash
# after: rm the 6 per_sample/*.json whose status != "completed"
PYTHONPATH=src python -m codex_agent.cli.run_openeqa \
  --questions data/open-eqa-v0.json \
  --data-root data/OpenEQA/scannet \
  --output-dir tmp/openeqa_eval_v3_tools_full1079_20260612 \
  --num-frames 8 --workers 4 --tools
```

The main pass scored **73.63** with 6 floor-scored failures (completion 99.44 %);
recovering those 6 lifted the headline to **73.96** at 100 % completion. The two
numbers bracket the rate-limit noise; **73.96 (100 % completion) is the
canonical figure.**

FROM samples

Per-category:

## Caveats (read before citing)

- **Judge mismatch.** We judge with `gemini-2.5-pro`; the OpenEQA paper uses
  GPT-4. MNAS is judge-sensitive, so **73.96 is not directly comparable to
  published OpenEQA leaderboard numbers.**
- **ScanNet only.** The 557 hm3d questions are excluded (no local assets). This
  is the ScanNet-split MNAS, not the full 1,636-question OpenEQA MNAS.
- **No prompt-only full-set baseline yet.** v3 is tools-enabled. A decision-grade
  **tools vs prompt-only** delta needs a matched full-set prompt-only run (or the
  canonical pilot fold). The v1/v2 smokes are too small (n=10, ±10–20 pp) for
  that comparison.
- **BEV is a schematic** (no `mesh.ply`): a top-down floor plan from ConceptGraph
  object footprints + camera trajectory, not a textured-mesh raster.
- **Rate-limit recovery.** 6/1079 questions needed a low-concurrency recovery
  pass after sticky 429s under 30 workers. The pipeline is correct; 30 workers is
  near the adapter pool's comfortable ceiling. Consider ≤ 20 workers next time to
  avoid the recovery step.
- **Data is local-only.** `data/open-eqa-v0.json` + `data/OpenEQA/scannet/` are
  gitignored symlinks; they never arrive via `git clone`.
